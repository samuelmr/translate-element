translate-element

A simple web component for translating text content in HTML pages.

Author your HTML content in any language. Mark the translatable sections with the lang attribute. Create a JSON file for translations. Add the web component to your page, and it will render a language switcher element for the languages found.

Features

  • Apply CSS styles like you would to a ul/li list
  • Automatic language detection from URL parameters (?lang=en)
  • Dynamic content translation (new elements added to DOM)
  • Fallback to default language if translation not found
  • Support for nested translatable elements
  • Attribute translation
  • Remembers the chosen language across pages (persist) and can follow the browser's language
  • Dispatches a languagechange event when the language changes
  • Embedded translations and a translation file can be combined

Usage

Basic Setup

1. Include the CSS and JavaScript files in your HTML:

<script src="https://unpkg.com/translate-element/translate-element.js"></script>

2. Add the translate element to your page:

<translate-element></translate-element>

3. Optionally, style the language switcher element using CSS:

<link rel="stylesheet" href="translate-element.css">

You can use translate-element.css as an example.

Creating Translatable Content

Mark elements for translation by adding the lang attribute with your default language:

Text Content

<h1 lang="en">Welcome</h1>
<p lang="en">This is a sample paragraph.</p>

Form Elements

<input type="submit" value="Submit" lang="en">
<input type="text" placeholder="Enter your name" lang="en">
<button lang="en">Click Me</button>

Attributes

If an element has the lang attribute, the following attributes are translated: alt, cite, href, label, placeholder, src, srcset, title, value.

<img src="image.jpg" alt="Sample image" lang="en">
<a href="/contact" title="Contact us" lang="en">Contact</a>

Embedded translations

You can maintain the translations directly within your HTML:

<h1 lang="en">Welcome</h1>
<h1 lang="de">Willkommen</h1>
<p lang="en">This is a sample paragraph.</p>
<p lang="de">Dies ist ein Beispielabsatz.</p>

Translation File (translations.json)

Create a JSON file with your translations. First level keys are the textContent of the elements to translate. The values are objects with a language codes as keys and corresponding translations as values. Example:

{
  "Text to translate": {
    "fi": "Käännettävä teksti",
    "sv": "Text att översätta",
    "de": "Text zu übersetz"
  },
  "Welcome": {
    "fi": "Tervetuloa",
    "sv": "Välkommen",
    "de": "Willkommen"
  }
}

Refer to the translation file in your HTML:

<translate-element src="translations.json"></translate-element>

Combining both

You can use embedded translations and a translation file on the same page. An embedded translation wins for its own language, and the file fills in the other languages. Here Swedish comes from the HTML and the other languages from the file:

<h1 lang="en">Welcome</h1>
<h1 lang="sv">Välkommen hit</h1>

Embedded translations are the elements in other languages among adjacent siblings that have the same tag name and a lang attribute. Each translation belongs to one element: if the group starts with an element in the page's language, translations follow their element; if it starts with a translation, they precede it.

<!-- "Welcome" owns sv, "Hello" owns de -->
<p lang="en">Welcome</p><p lang="sv">Välkommen</p>
<p lang="en">Hello</p><p lang="de">Hallo</p>

<!-- each fi option belongs to the en option after it -->
<option lang="fi" value="1">yksin</option><option lang="en" value="1">alone</option>
<option lang="fi" value="2">kumppanin</option><option lang="en" value="2">partner</option>

Untranslated content

An element with a lang attribute but no translation of its own is reported in the console. By default it also loses the attribute, so it is shown in every language: a missing entry in the translation file then shows up as untranslated text instead of hiding a button or an input field.

This doesn't happen when the element has siblings in other languages next to it, because then the content is being translated by hand. In this example only C is shown in Swedish:

<p lang="en">A</p>
<p lang="en">B</p>
<p lang="sv">C</p>

Add the strict attribute to keep the lang attribute on every untranslated element, so that it is hidden in the other languages:

<translate-element strict src="translations.json"></translate-element>

Language selection

Remembering the language

By default the chosen language lives only in the ?lang= query parameter, so it is lost when the visitor follows a link to another page. Add the persist attribute to remember the choice made with the switcher in localStorage.

To start in the browser's language for first-time visitors, add prefer-browser-language as well:

<translate-element persist prefer-browser-language src="translations.json">
</translate-element>

The language shown on load is the first of these that the page has content for:

  1. The ?lang= query parameter. It is never stored, so a shared link does not change the visitor's own preference.
  2. The stored choice (persist).
  3. The browser's preferred languages (prefer-browser-language). A regional tag such as fi-FI matches fi.
  4. The page's own language.

If localStorage is not available, the choice is simply not remembered.

Source language

The language of the content you author is taken from the lang attribute of the nearest ancestor of <translate-element> (usually <html lang="en">). If there is none, the default attribute is used, and otherwise en.

<translate-element default="fi" src="translations.json">
</translate-element>

Switching language from script

Set the current attribute to switch the language, and listen to the bubbling languagechange event to react to changes. The event is dispatched once per change, also for the initial choice on load, with the new and the previous language in detail. The lang attribute of <html> is kept up to date too, so you can style on :root[lang="sv"] or observe it with a MutationObserver.

document.querySelector('translate-element').setAttribute('current', 'sv')
document.addEventListener('languagechange', (e) => {
  console.log(e.detail.language, e.detail.previousLanguage)
})

Good to know

  • The switcher is a ul of li items with an a link (hreflang, rel="alternate") in each. The active item has the class selected. Clicking one updates ?lang= in the address bar without reloading the page, except on file:// pages.
  • An element with a lang attribute but no translation is shown in every language, unless it has siblings in other languages or strict is set (see Untranslated content).
  • Translations in the JSON file are inserted as HTML, so you can use tags such as <code>. Only use translations you trust.
  • Translated copies keep the inline event handlers of the original, and their id gets a language suffix, such as heading-sv.
  • The label of option and optgroup elements is translated, including options inside an optgroup, and the selected option stays selected when the language changes.
  • A title element with a lang attribute is translated too.
  • When an element in a new language is added to the page later, the language is added to the switcher.

Console output

If the HTML content contains an element with the lang attribute, but no translations are found in the translations.json file, the web component will output the textContent of the untranslated element into the developer console.

Upgrading from 3.x

Version 4.0 doesn't change the API, but some pages may render differently:

  • An embedded translation now wins over the translation file for its own language. Previously both were shown.
  • Each embedded translation belongs to one element. Previously any neighbour with a lang attribute counted, so two adjacent untranslated elements in the page's language were hidden in every other language; now they are shown.
  • New: the strict attribute.
